## 这是什么

一个跑在本机的 QQ 机器人，两条独立实现并存：

| 通道 | 实现 | 端口 | 特点 |
| --- | --- | --- | --- |
| **legacy**（旧机器人） | NoneBot2 + `plugins/ai_chat` | 8080 | 功能全：记忆、表情包、主动聊天、群管理 |
| **dsh**（检修） | DSH 桌面应用 + `dsh-onebot-qq` 插件 | 8643 | 直接用 DSH 的模型能力，功能少但可调试 |

两条通道的对话记录互相独立：legacy 写 `data/bot.db`，dsh 写 `~/.dsh/sessions/`。

---

## 核心架构：双连接 + 一个开关

**NapCat 同时挂着两条反向 WS 连接**，永不主动断开：

```
NapCat (QQ 235286703)
  ├─ ws://127.0.0.1:8080/onebot/v11/ws  → NoneBot（legacy）
  └─ ws://127.0.0.1:8643/ws             → DSH 插件（dsh）
```

同一条消息两边都收到，但**只有一个真正处理**：

```
E:\qqbot\.tmp\active-channel.txt     内容：legacy 或 dsh
```

- `legacy` → 旧机器人处理，DSH 静默
- `dsh` → DSH 处理，旧机器人静默

### 为什么这样设计

早期是「改 NapCat 配置来切换指向」。每次切换会触发 NapCat **热重载** OneBot11 适配器，新旧客户端实例打架，导致连接被对端反复踢掉，日志刷「连接意外关闭 / 5 秒后重连」，QQ 消息全丢。

改成双连接后，**切换只写一个文本文件，NapCat 连接完全不动**，那个坑从根上消失。

代价：开关指向的那一方必须真的活着，否则两边都静默。

## 切换通道

```powershell
cd E:\qqbot
.\scripts\set-channel.ps1 status   # 看当前
.\scripts\set-channel.ps1 dsh      # 交给 DSH
.\scripts\set-channel.ps1 legacy   # 交回旧机器人
```

在 QQ 里也可以用自然语言触发（见下节）。

---

## QQ 里的指令

| 指令 | 谁处理 | 行为 |
| --- | --- | --- |
| `检修` | legacy 侧 `plugins/relay_switch` | 第 1 次回「你干嘛」（二次确认）；120 秒内再发一次才真的切到 dsh |
| `恢复` | dsh 侧（靠 `AGENTS.md` 指引） | 直接切回 legacy |

**`AGENTS.md` 是给 DSH 会话看的操作手册**，里面写明了收到「检修」/「恢复」要立即执行什么，以及禁止自行摸索。

## 启动 / 停止

### 启动旧机器人

```powershell
cd E:\qqbot
Start-Process -FilePath "E:\qqbot\.venv\Scripts\python.exe" `
    -ArgumentList "-u", "bot.py" `
    -WorkingDirectory "E:\qqbot" -WindowStyle Hidden `
    -RedirectStandardOutput "E:\qqbot\.tmp\bot-stdout.log" `
    -RedirectStandardError  "E:\qqbot\.tmp\bot-stderr.log"
```

### 启动 NapCat（需要扫码）

```powershell
cd E:\qqbot
.\scripts\start_napcat_scan.ps1
```

它会清掉免密登录入口、启动 NapCat、把二维码复制成 `assets/qr-<时间>.png`。

**扫码前必须先把手机 QQ 切到 235286703**，否则会登成主号 1450520453（后果严重：主号会以自己身份接收所有群消息）。

### 健康检查

```powershell
cd E:\qqbot; .\scripts\set-channel.ps1 status        # 一次看全
try { (Invoke-WebRequest -Uri "http://127.0.0.1:8080/healthz" -TimeoutSec 4 -UseBasicParsing).Content } catch { "DOWN" }
Get-Content "$env:USERPROFILE\.dsh\media\onebot\qq-trace.jsonl" -Tail 5
```

正常状态应该是：

```
活跃通道: legacy 或 dsh
旧机器人 8080: 在监听
DSH 8643   : 在监听
NapCat client 数: 2      ← 必须是 2
```

## 排查入口（按优先级）

1. **DSH 侧有没有收到消息** → 看 `qq-trace.jsonl` 最后几条
   - 有 `inbound ok:true` → 传输层通了
   - 有 `inbound ok:false, reason:"活跃通道不是 dsh，已忽略"` → 正常，开关在 legacy
   - 完全没有新记录 → 传输层断了，看 NapCat 日志
2. **NapCat 日志** → `Get-ChildItem E:\qqbot\.tmp\napcat-scan-*.log | sort LastWriteTime -desc | select -first 1`
   - 刷「连接意外关闭 / 5 秒后重连」→ 用 `toggle-napcat-ws.ps1` 修
3. **8080 健康** → `healthz` 的 `bots` 是不是 1
4. **开关指向** → `set-channel.ps1 status`

详细故障处理见 `AGENTS.md` 的「常见故障」。
