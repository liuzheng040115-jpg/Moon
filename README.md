# QQ AI 机器人（NoneBot2 + OneBot v11 + DeepSeek）

一个可以直接跑起来的 QQ 聊天机器人：私聊随便聊，群里 @它或 `#` 一定回，其他时候自己判断要不要接话；带多轮记忆、跨聊天记录查询、管理员跨群指挥、限流、图片 OCR、表情包收藏与发送、长回复自动拆成多条短消息。好友请求也会自己判断通过（广告号拒绝），管理员拉群自动同意；新好友、进群、被踢、被禁言、模型连续出错会私聊通知你。

- 框架：NoneBot2 2.5 + OneBot v11 适配器
- 协议端：NapCat（已内置到 `tools/`，个人号扫码登录）
- 模型：DeepSeek 兼容接口（默认 `deepseek-v4.1-flash`，可换官方或任意中转）
- 记忆：SQLite 持久化，重启不丢
- 人设：私聊 `1450520453` 时是 ds大肥鱼；群里和其他账号是有自己名字的普通人；读项目的 AI 也按 ds大肥鱼 说话
- 运维：`/status` 运行状态、`GET /healthz` 健康检查

> ⚠️ 个人号走 OneBot 协议属于非官方用法，有被风控的风险，建议用小号。合规场景请改用 QQ 官方机器人 API。

## 0.5 登录只走扫码（安全默认）

项目里**没有任何 QQ 密码**；NapCat 能免密登录，是因为它读本机 QQ 的登录态。为避免再登成管理员大号：

- 启动前会清空 `NAPCAT_QUICK_ACCOUNT` / `NAPCAT_QUICK_PASSWORD` / `NAPCAT_QUICK_PASSWORD_MD5`
- 清空 WebUI 的 `autoLoginAccount`，不传 `-q` 参数
- 插件侧再兜一层：`AI_BOT_QQ=2055392980`，登成别的号时直接拒绝处理
- 只保留 `onebot11_2055392980.json`，其他账号的 WS 配置改名 `.disabled`

只扫码启动：

```powershell
.\scripts\start_napcat_scan.ps1
```

脚本会清掉免密入口、启动 NapCat，并把二维码复制成 `assets/qr-<时间>.png`（唯一文件名，避免看图缓存）。

已经装好环境的话，直接：

```powershell
.\start_all.bat   # 机器人 + NapCat 各开一个窗口；NapCat 窗口扫码
# 或者只启动机器人：
.\run.ps1
```

首次从零开始：

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
# 编辑 .env，填 DEEPSEEK_API_KEY
.\run.ps1
```

看到这行说明在等 QQ 连进来：

```
OneBot v11 反向 WS 监听: ws://127.0.0.1:8080/onebot/v11/ws
```

### 当前使用的模型

本机 `.env` 配的是中转站（one-api），实测可用：

| 模型 | 实测首包 | 说明 |
| --- | --- | --- |
| `deepseek-v4.1-flash` | ~3.3s | 默认，速度/质量均衡 |
| `deepseek-flash` | ~2.4s | 更快，质量略低 |
| `deepseek-v4-pro` | ~4.4s | 更聪明，慢一些 |

这三个都是**推理型模型**：先输出 `reasoning_content` 再出正文，所以 `AI_MAX_TOKENS` 要给足（现在 1500）。设太小会出现「回复为空」。

## 2. 接入 QQ（NapCat）

### 2.1 安装

```powershell
.\scripts\setup_napcat.ps1
```

会检查 QQ NT 安装、下载 `NapCat.Shell.Windows.Node.zip`（自带 Node）并解压到 `tools\NapCat`。国内直连 GitHub 慢时会自动走镜像。

### 2.2 启动并扫码

日常用一键脚本（机器人 + NapCat，仅扫码）：

```powershell
.\start_all.bat
```

只想重新拿一张二维码（会先清掉免密登录入口）：

```powershell
.\scripts\start_napcat_scan.ps1
```

也可以只启动 NapCat：

```powershell
.\tools\NapCat\napcat.bat
```

终端会打印二维码，同时保存到 `tools\NapCat\napcat\cache\qrcode.png`。用**准备做机器人的 QQ** 扫码，手机上确认登录。

> 不要用 `-q <QQ号>` 启动 NapCat：那是快速登录，会拿本机历史登录态直接进号，可能登成管理员大号。扫码脚本和 `start_all.bat` 都不会传这个参数，并且会清掉 `NAPCAT_QUICK_*` 环境变量与 WebUI 的 `autoLoginAccount`。

- 二维码约 2 分钟有效；过期就重启 NapCat 重新生成。
- 登录成功后 NapCat 窗口会持续输出收发的群消息，属于正常现象。

### 2.3 配置反向 WS（登录后运行一次）

```powershell
.\scripts\configure_napcat.ps1
```

脚本会从 `.env` 读 `ONEBOT_ACCESS_TOKEN` 和 `PORT`，通过 NapCat WebUI API 把反向 WS 指到：

```
ws://127.0.0.1:8080/onebot/v11/ws
```

消息格式设为 `array`，token 与 `.env` 一致。

### 2.4 验证

机器人日志出现：

```
OneBot V11 | Bot <QQ号> connected
```

就表示接入成功。然后在 QQ 里：

- 私聊机器人发「你好」
- 群里 `@机器人 你好`，或以 `#` 开头说话

也可以访问 `http://127.0.0.1:8080/healthz`，返回 `{"ok":true,"bots":1,...}` 即正常。

> 换账号时：NapCat 会为新 QQ 生成新的 `onebot11_<QQ>.json`，重新运行一次 `.\scripts\configure_napcat.ps1` 即可。

## 3. 触发方式与指令

| 场景 | 行为 |
| --- | --- |
| 私聊 | 直接说话就有回复（`AI_REPLY_PRIVATE=false` 可关） |
| 群聊 | 默认 `auto`：`@机器人` 或 `#` 开头一定回；其他时候它自己判断要不要接。也可选 `at` / `at_prefix` / `prefix` / `all` |
| 指令 | 仅管理员（`SUPERUSERS`，当前 `1450520453`），且**只在私聊生效**：`/help`、`/reset`、`/reset all`、`/status`。群里发指令、或其他账号发指令都不会有任何反应，避免暴露 |

群里被 @ 时，第一条回复会带引用，方便对上号。回复太长会自动拆成多条短消息（默认每条 28 字以内、最多 4 条），分条之间隔 0.4～1.2 秒，只有第一条带引用。

**群聊休眠/高读机制（默认 `AI_GROUP_TRIGGER=auto`）**：

- 被 `@`、被回复、叫它名字、`#` 开头 → 唤醒：回看最近 10 分钟群聊；如果这条是引用，读引用那条前后各 6 条
- 唤醒后进入 3 分钟高读状态：每条群消息都会判断“是不是在跟我说 / 接着我参与的话题”，有关就接，无关就回 `[SKIP]`
- 高读期内它每回一句，窗口从回复时刻再续 3 分钟
- 3 分钟没接过话 → 自动休眠：消息照收、照记上下文，但不逐条分析、不调模型
- 休眠时保留原来的随机/提问/接话头判断：命中才低成本唤醒，没命中就不理；普通闲聊不打扰
- 休眠时只认 `@`、回复它、叫名字、`#`；随机命中也会短暂醒来
- 这句 @ 了别人、或回复的是别人的消息 → 不抢话

它不会逐条回复；但不会再像纯问答机器人那样只等你 @。

**群聊上下文**：机器人会默默记住最近 20 条群消息（含昵称、机器人自己的回复），自己接话或被人叫到时一起带给模型，所以它能接上前面的梗、知道“他/她”指谁。

- 每条群消息会带短 ID 和“回复 #ID”的关系；@ 别人、@ 你也会标出来
- 有人说“问你呢 / 你自己看前面 / 刚才那句”时，它会先找最近 @ 它或被回复的那条，再回答；实在不确定会反问“你问哪句”，不再只抓“表情包”这种关键词乱猜

### 说话像真人（不是靠语气词硬装）

聊天记录里最明显的“人机感”不是内容，是格式：改之前机器人 80% 的回复以“。”结尾、平均 23 个字；同一批人类群聊平均 7 个字，90% 不带句末标点。现在做了几件事：

- 提示词改成“先像人在 QQ 随手打字”：多数 3～15 字、一句；句末不加句号；允许只回“？”“行”“笑死”这类短反应
- 程序侧兜底：发送前去掉句末句号、把句中的“。”换成“，”，分条后不留在逗号上
- 不允许每句都怼人、抖机灵或提鱼；会把最近 4 句回复带给模型当反向参考，避免重复“行行行/有事说事/别……”这些开头
- 发图时正文可以空着，不强制每张图配一句点评
- 单条上限降到 28 字，长回复更容易拆成两条
- 开了 `frequency_penalty` / `presence_penalty`，压复读和套话
- 性格更有活力：多接梗、多笑、偶尔主动问；明确禁止装深沉、中二、风/夜/月亮/孤独这类文艺腔

想更短就调小 `AI_SEND_CHARS`（比如 22），想让它醒着的时间更长就调大 `AI_GROUP_ACTIVE_SECONDS`。

### 它会自己决定改资料 / 发空间

朋友在私聊里可以提“换头像 / 换昵称 / 换签名 / 发条空间说说”，但由它按心情判断，不是有求必应：十次里通常只答应两三次，对方越用命令口气越不干，刚换过资料 30 分钟内会更懒。

- 支持：头像（对方发图，或给 http(s) 图片链接）、昵称、个性签名、QQ 空间说说（纯文字，或带对方刚发的一张图）
- 空间默认好友可见；对方明确说“公开/所有人”才用所有人可见，也可以说“仅自己可见”；同一人 6 小时内最多发一条
- 不支持：QQ 背景——协议没有这个接口，它会直接说换不了
- 只在私聊：群里提会被挡回“私聊说”，不会在群里执行
- 头像会先下载校验（必须是图片、不超过 5MB、不能是内网地址），再交给 NapCat；改完是真的生效
- 说“换这个头像”时，如果你上一句才发的图，它会用最近那张，不会因为这条消息没带图就找不到
- 管理员可以直接发 `/avatar`（用最近一张图）或 `/avatar 图片链接` 强制换；`/sign` 查看当前签名，`/sign 内容` 强制改
- 只有对方明确提到“头像/昵称/签名/空间/说说”才会执行；头像 URL 必须是对方真的发过或写过的，防止提示词注入乱改
- 模型答应后在回复末尾写一条隐藏指令，程序执行后会把指令删掉，不会发给对方
- 换签名/发空间的追问（比如“文艺点那种”“没变啊”）也算在刚才的意图里，不会因为这句话里没有“签名”两个字就被拦
- 签名和说说会写人话，不写“风把夜吹薄了”这种中二句子

### 会上网查资料

- 遇到新闻、价格、天气、赛事、版本、人物近况这类可能过时或不确认的信息，模型会写 `[[SEARCH:搜索词]]`，程序去 Bing（失败再试 DuckDuckGo）查摘要，再让它根据摘要回答
- 只读搜索摘要，不保证 100% 正确；查不到会直接说“没查到”，不会硬编
- 日常闲聊不搜；不想让它联网就设 `AI_WEB_SEARCH=false`
- 搜索词会发给搜索引擎，不会写进长期记忆

### 好友请求和入群邀请

它自己处理，不用你手动点：

- **正常的好友请求直接通过**，并主动发一句“加了/有事说”这样的短句；验证消息写“你好/在吗”会顺着回一句。
- **广告号直接拒绝**：验证消息里出现刷单、兼职、返利、贷款、加微信、博彩、卖号这类词就不通过。
- 每小时最多自动通过 `AI_FRIEND_MAX_PER_HOUR` 个（默认 6），超出的先拒绝，防止被批量加。
- 通过/拒绝都会私聊通知管理员，`/status` 里也能看到通过/拒绝数量。
- 管理员（`SUPERUSERS`）邀请它进群会自动同意；陌生人拉群不会理。
- 想关掉自动通过：`AI_FRIEND_AUTO_ACCEPT=false`（请求会留给你处理）；不想打招呼：`AI_FRIEND_GREET=false`。

### 重要事件会私聊通知你

不想收就设 `AI_NOTICE_ENABLED=false`；想换通知对象改 `AI_NOTICE_QQ`。通知本身不会写进对话记忆或跨聊天记录。

### 会主动找你聊天

- 默认每 2～5 小时随缘发一条，每天最多 3 条；凌晨 0～8 点不发；你刚聊过 45 分钟内不打扰。
- 内容按当前时间和你们最近的聊天生成，可以带点小脾气、耍性子、撒娇、催你、抱怨你不理她，不是“在吗”这种客服问候。
- 想现在就来一句：私聊发 `/proactive`（或 `/主动`），不受频率和时段限制。
- 不想被找：`AI_PROACTIVE_ENABLED=false`；频率和时段见下面的配置表。

### 图片和表情包

- **收图片**：优先用 `AI_VISION_MODEL` 指定的视觉模型描述；本机已设为 `deepseek-v4.1-flash`，实测能直接看图。没配视觉模型就用 NapCat 的 OCR 识别图里的文字。纯照片没有视觉模型时它会老实说“图打不开”，不会编。
- **收表情**：QQ 商城表情/自带表情会带 `summary` 或表情 ID，它能接梗；有合适的收藏就回一张。
- **收藏表情**：把真正高质量、清晰、以后会反复用的表情存进 `data/stickers/`，同时记下描述和“适合什么场合”；普通可爱、糊图、截图、照片不存。你（1450520453）明确说“存一下/收藏这个”时一定存。自动收藏同一会话 15 分钟内最多一张、每天最多 5 张，避免一口气全收；最多 50 张，`/reset all` 会连文件一起清空。
- **发表情**：只用收藏的表情，格式 `[[STICKER:#编号]]`；**私聊、群里都能发**。模型自己决定发不发，发完文字后单独发一张图，一次最多一张；也可以只发图不配字。
  - 不再使用任何自带/自造表情图；`assets/stickers/` 和 `scripts/make_stickers.py` 已删除。
  - **不发 QQ 自带的黄豆表情**（模型写了 `[[FACE:…]]` 或旧的自带表情名都会被忽略）；不想让它发表情就设 `AI_STICKERS=false`。
- 语音和文件内容仍然看不了，遇到会直接说明。

### 管理员查其他聊天的记录

只有 **1450520453 的私聊**能查。所有群聊/私聊消息（包括机器人自己的回复）都会写进本地 SQLite 的 `chat_log`，默认保留 7 天或 5000 条；`/reset all` 会一起清空。首次启用或日志为空时，会从现有的群聊/私聊记录回填一次。

可以直接问：

- “今天群里都说了些什么”
- “隔壁群刚才聊了什么”
- “今天哪些人找你聊了些什么”
- “昨天私聊都聊了什么”

实现上是**按需检索**：只有检测到这类问句时，才把相关记录临时拼成一段系统提示交给模型；**不会写进日常对话记忆**，也不会在平时聊天里主动提起其他群。其他账号问这些不会触发检索。

### 管理员可以直接指挥去群里

也只有 **1450520453 的私聊**可以。直接说：

- “去小团体群说晚安”
- “去群里发个收藏表情”
- “去隔壁群问问谁还在”
- “去群里告诉他们今晚八点开会”

它会先拿到自己所在的群列表，群名清楚就直接去；不确定去哪个群、或不确定发什么，会先反问。一次只执行一条，支持发文字或收藏表情（`#编号`），发完给你回执。

群必须在白名单里、且不在黑名单，否则拒绝；违法、骚扰、刷屏内容也会拒绝。代发的消息同样会写进该群上下文和跨聊天记录。

## 6. 常见问题

**日志没有 `Bot connected`** → 检查 `.env` 的 `ONEBOT_ACCESS_TOKEN` 与 NapCat 配置是否一致，然后重新运行 `.\scripts\configure_napcat.ps1`。token 不一致会直接 403。

**扫码后没反应 / 二维码失效** → 关掉 NapCat 窗口重新运行 `.\tools\NapCat\napcat.bat`，二维码约 2 分钟有效。

**群里 @ 了没反应** → 先看它是不是刚重启/掉线（日志要有 `Bot <QQ> connected`）；普通人 60 秒内 @ 超过 6 次会被限流；群是否在白名单/黑名单；群里发 `/help` 这类指令本来就不响应。只 `@` 不带字以前会被忽略，现在会回“在，说。”。

**群里太安静** → 休眠时普通消息不逐条分析，只按随机/提问概率决定要不要醒；先 `@` 它、回复它或叫它名字一定唤醒。想更常随机插话就调高 `AI_GROUP_AUTO_CHANCE`，想醒久一点调大 `AI_GROUP_ACTIVE_SECONDS`，或把 `AI_GROUP_TRIGGER` 改成 `all`（每句都回，慎用）。

**群里太吵** → 调小 `AI_GROUP_ACTIVE_SECONDS`、调低 `AI_GROUP_AUTO_CHANCE`，或改回 `AI_GROUP_TRIGGER=at_prefix`，只响应 @ 和 `#`；休眠机制本身就会在 3 分钟没接话后闭嘴。

**加好友没自动通过** → 先看验证消息是不是像广告（刷单、兼职、加微信这类会被拒）；`AI_FRIEND_AUTO_ACCEPT` 是否被关；一小时内超过 `AI_FRIEND_MAX_PER_HOUR` 会先拒绝。如果日志里完全没有“已通过/已拒绝好友请求”，说明 NapCat 没把请求事件转过来，重启 NapCat 再试。管理员邀请进群会自动同意，陌生人拉群不会。

**朋友发 `/status`、`/reset` 没反应** → 正常。指令只对 `SUPERUSERS` 里的管理员、且只在私聊开放；群里发也不会响应（避免把模型、记忆这些信息暴露给群友）。把 `SUPERUSERS` 改成你**个人 QQ** 的号（不是机器人登录的号），重启机器人。

**机器人回「还没配置 API Key」** → `.env` 里 `DEEPSEEK_API_KEY` 是空的。

**401 / 402 / 429 / 404** → Key 无效 / 余额不足 / 被限流 / 模型名或 BASE_URL 不对。404 时用 `GET {BASE_URL}/models` 看中转站实际给了哪些模型。

**老是 429 被限流** → 已内置 429 自动退避重试和全局节流；如果还频繁出现，说明这个 Key 的 RPM 很低：把 `AI_MODEL_MIN_INTERVAL` 调大（比如 1.5）、`AI_MAX_CONCURRENCY` 降到 2、`AI_GROUP_ACTIVE_SECONDS` 调小，或换 Key / 换站点。日志里的“模型调用失败: ... 429”会带上服务端建议的等待时间。

**让它换头像它不换** → 正常，它本来就不是百依百顺；私聊、发图、别用命令口气，刚换过 30 分钟内会更懒。它只答应头像/昵称/签名，换背景会说没有这功能。

**换头像失败** → 看机器人日志里的“资料修改失败”；图片链接要能公网访问、是图片、小于 5MB，QQ 也可能临时风控。

**回复是空的** → 推理模型把 token 花在思考上了，调大 `AI_MAX_TOKENS`（1500~2000）。

**重启后记忆还在吗** → 在。数据在 `data/bot.db`；想彻底清空可以停机器人后删除 `data/`，或在聊天里 `/reset all`。

**数据库 locked** → 同时开了多个 `bot.py`，只保留一个。

**中文乱码** → Windows 控制台执行 `chcp 65001`，或设置 `PYTHONIOENCODING=utf-8`。PowerShell 脚本需要保存为 UTF-8 with BOM。

**登录掉线/发不出消息** → 个人号风控，换小号、降低频率、别群发；长期用建议转官方 API。

## 7. 安全建议

- `.env`、`data/`、`tools/` 都已在 `.gitignore` 里，不要把 Key、token、聊天记录提交到仓库。
- `ONEBOT_ACCESS_TOKEN` 用随机串，不要用默认的 `change-me-plz`。
- 机器人账号建议用小号；群白名单能避免它被拉进不相关的群。
- **登录只扫码**：不要用 `-q`、不要配 `NAPCAT_QUICK_ACCOUNT` / `NAPCAT_QUICK_PASSWORD`，WebUI 的自动登录账号保持为空。项目里没有 QQ 密码，但 NapCat 能读到本机 QQ 登录态，所以免密登录有登错号的风险。
- 填好 `AI_BOT_QQ`：NapCat 万一登成别的号，插件会拒绝发消息、改资料、读聊天，只在日志报错。
- 如果发现登成了大号：手机 QQ → 设置 → 账号安全 → 登录设备管理，把 PC/NapCat 踢下线；必要时改密码。
- `C:\Users\<你>\Documents\Tencent Files\1450520453` 是本机 QQ 的聊天数据，不属于本项目；NapCat 登错号期间可能往那里写过缓存，介意可以清理。
